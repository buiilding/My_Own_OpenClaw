## medium: Turn refs are stored unnormalized when inferred from messages

id: fnd_sig-feat-service-37c269c6cc-4d39_5d19f44cde

evidence:

- frontend/src/renderer/features/chat/stores/chatStore.ts:331-336 (addMessage)
- frontend/src/renderer/features/chat/stores/chatStore.ts:360-365 (updateMessage)

The explicit registration and lookup path trims turn refs before storing and resolving them, but the implicit registration done by addMessage and updateMessage writes message.turnRef / updates.turnRef directly. If an upstream event supplies a turnRef with leading or trailing whitespace, addMessage stores the untrimmed key while resolveConversationRefForTurn trims the lookup key, so the conversation cannot be resolved for that turn. updateMessage also treats whitespace-only turn refs as valid because it checks length without trimming. recommendation:
Normalize turn refs in addMessage and updateMessage with the same trim logic used by registerTurnConversationRef, and ignore empty normalized turn refs.

test analysis:

suggested regression test:
Add a store unit test that adds and updates messages with padded and whitespace-only turnRef values, then verifies resolveConversationRefForTurn returns the conversation only for normalized non-empty refs.

minimum fix scope:
Change the implicit turn-ref registration branches in addMessage and updateMessage to compute a normalizedTurnRef before updating turnConversationRefs.

repro:
