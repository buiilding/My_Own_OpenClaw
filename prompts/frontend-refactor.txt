Refactor the WindieOS frontend for long-term agent-loop maintainability.
Do not code until the plan is approved.

Start with a no-code design package:
- state machine for all execution phases
- ownership map across renderer/main/sidecar
- current touchpoint inventory
- target architecture
- migration plan
- explicit invariants for focus, click-through, overlay visibility, stop control
  availability, and screenshot timing

Then implement in small phases with no unintended behavior change:
- centralize surface lifecycle control into a single `SurfaceOrchestrator`
  (or equivalent) with typed transition APIs
- remove duplicated toggles and timing logic spread across files
- standardize backend-event-to-UI contracts for tool phases and recovery metadata
- keep dev/prod gating explicit and test both paths
- add deterministic correlation-id logs for each state transition, retry, and
  terminal failure so race conditions are debuggable from logs

Testing requirements:
- add scenario tests for race-prone flows:
  tool start/stop timing, click-through windows, hide-before-capture/show-after,
  focus verification retries and bounded exhaustion, and recovery after failed
  surface prep
- update architecture docs with new boundaries and event contracts

Acceptance criteria:
- current behavior preserved
- fewer files touched per future feature
- single source of truth for surface state
- passing tests proving transition stability
